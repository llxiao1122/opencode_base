# Cipher 架构演进路线 — v3.1 → v4

## 当前架构（v3.1）

```
消息 ──▶ L1 Ingress ──▶ L2 Intent ──▶ L3 Reasoning ──▶ L4 Execution ──▶ L5 Response ──▶ L6 Reflection
         │               │              │                │                │               │
         │ 关键词规则     │ 正则提取      │ LLM 推理       │ Route 硬编码    │ LLM 合成      │ 固定执行
         │ classify()    │ if/else 责任  │ (仅 event)    │ switch/case    │              │ (3600s cooldown)
         ▼               ▼              ▼                ▼                ▼               ▼
       route=""        ctx.events     ctx.decision     handler()        reply=""         obs_write
```

**问题**：6 层固定执行，每层都是硬编码规则/条件分支，不灵活。

---

## Phase 0 — Embedding 路由替换

```
消息 ──▶ L1 Ingress ────▶ L2~L6 (不变)
         │
         │  embed() ──▶ FAISS ──▶ route + confidence
         │              ↑
         │         state/route_seeds.json
         │
         ▼
       route="event|task|profile|knowledge"
       confidence=0.0~1.0
```

| 替换前 | 替换后 |
|--------|--------|
| `CLASSIFY_RULES` 关键词字典 | `route_seeds.json` 每条 5-10 个种子查询 |
| 关键词命中→路由 | 语义相似度 >0.85→路由 |
| 关键词未命中→语义降级 | 0.6~0.85→确认，<0.6→默认 event |

## Phase 1 — Confidence 穿透

```
                ┌─ confidence > 0.8 ──▶ L3 Reasoning ──▶ L5 Response (LLM)
                │
L1 ──▶ L2 ──────┼─ confidence 0.5~0.8 ─▶ L5 Response (LLM, 带确认)
                │
                └─ confidence < 0.5 ──▶ L5 Response (模板回复, 无 LLM)

                    route=task ──▶ SKIP L3 ──▶ L4 Execution
                    route=profile ──▶ SKIP L3~L4 ──▶ L5 Response
```

**每层决策表**：

```
L1:  route + confidence
L2:  confidence > 0.6 → 执行完整提取
     confidence < 0.6 → 只提取基本信息
L3:  route=event && confidence > 0.6 → LLM 推理
     其他 → 跳过
L4:  confidence > 0.8 → 自动执行
     confidence < 0.8 → 待确认
L5:  confidence > 0.4 → LLM 合成回复
     否则 → 模板回复
L6:  route=event || 含触发词 → 执行
     否则 → 跳过
```

## Phase 2 — Decision Log + 自学习

```
                     ┌─▶ user_corrected=false ──▶ 记录成功案例
消息 ──▶ Pipeline ───┤
                     └─▶ user_corrected=true ──▶ 记录纠错 ──▶ 更新种子

历史纠错 ──▶ learner.py ──▶ 更新 route_seeds.json ──▶ 重建索引
                              │
                              ├─ 高频纠错 → 自动修正种子
                              └─ 低频纠错 → 人工审核标记
```

**数据流**：

```
Pipeline 决策
    │
    ▼
state/decision_log.jsonl
    │  [{time, msg, route, confidence, user_corrected, corrected_route}]
    │
    ▼
skills/correction/learner.py (手动触发或 cron)
    │
    ├── 聚类纠错模式
    ├── 更新 route_seeds.json
    └── 标记老化规则（>3 次纠错）
```

## Phase 3 — Agentic Pipeline

```
Pipeline Orchestrator
    │
    ├── registry = [
    │       IngressModule(priority=1,  trigger=lambda ctx: True),
    │       IntentModule(priority=2,   trigger=lambda ctx: True),
    │       ReasoningModule(priority=3, trigger=lambda ctx: ctx.route=="event" && ctx.confidence>0.6),
    │       ExecutionModule(priority=4, trigger=lambda ctx: ctx.confidence>0.8),
    │       ResponseModule(priority=5,  trigger=lambda ctx: True),
    │       ReflectionModule(priority=6, trigger=lambda ctx: "如果" in ctx.raw or ctx.route=="event"),
    │  ]
    │
    └── run(ctx):
            for module in sorted(registry, key=lambda m: m.priority):
                if module.should_run(ctx):
                    module.run(ctx)
                    if ctx.abort: break
```

**模块接口**：

```python
class PipelineModule(ABC):
    name: str
    priority: int

    @abstractmethod
    def should_run(self, ctx: RequestContext) -> bool:
        """是否该执行"""
        pass

    @abstractmethod
    def run(self, ctx: RequestContext) -> None:
        """执行"""
        pass
```

**当前 6 层注册为 6 个模块，新增功能只需加新模块**：

```
新增模块：AudioModule(解析语音消息) — 加一个类，不影响其他层
新增模块：TranslateModule(翻译) — 同上
调试：注释掉 ReflectionModule 即可禁用反思
```
